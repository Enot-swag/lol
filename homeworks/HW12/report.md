# HW12 – временные ряды: temporal split, baseline-модели и GRU-прогноз

## 1. Кратко: что сделано

- **Датасет**: использован файл `S12-hw-dataset.csv` с почасовыми данными за период с января по июнь 2025 года. Прогнозировалось значение `target` на следующий час (горизонт = 1).

- **Temporal split**: данные разбиты в хронологическом порядке на train (70%), validation (15%) и test (15%) без перемешивания.

- **Сравниваемые подходы**:
  - **B1** – naive-last (прогноз = последнее известное значение)
  - **B2** – moving-average (скользящее среднее с окном 24 часа)
  - **B3** – Ridge регрессия на лаговых, rolling и календарных признаках
  - **R1** – GRU нейросеть с оконным представлением (window_size = 168 часов)

- **Лучший подход**: GRU (R1) показал наименьшую ошибку на validation (MAE = 4.89) и подтвердил результат на test (MAE = 5.12). Нейросетевая архитектура лучше уловила сложные нелинейные зависимости и сезонные паттерны по сравнению с линейными baseline'ами.

## 3. Данные и постановка задачи

- **Датасет**: `S12-hw-dataset.csv`
- **Целевая колонка**: `target`
- **Частота временного ряда**: почасовые данные
- **Горизонт прогноза**: 1 час вперед (next-step forecasting)
- **Размер датасета**: 4320 наблюдений
- **Диапазон дат**: 2025-01-01 00:00:00 – 2025-06-29 23:00:00
- **Дополнительные внешние признаки**: в исходном датасете отсутствуют, использовались только производные признаки от `target`

**Комментарий**: ряд демонстрирует ярко выраженную суточную сезонность (период 24 часа) и возможную недельную сезонность (168 часов). Наблюдается общий восходящий тренд и локальные выбросы. Пропуски отсутствуют, что упрощает предобработку. Основная сложность прогноза – уловить как краткосрочную (суточную), так и долгосрочную (недельную) периодичность при наличии тренда.

## 4. Temporal split и признаки

### 4.1. Разбиение по времени

- **Как выполнен split**: данные отсортированы по дате, затем выполнено последовательное разбиение:
  - Train: первые 70% наблюдений (2025-01-01 – ~2025-04-20)
  - Validation: следующие 15% наблюдений (~2025-04-21 – ~2025-05-20)
  - Test: последние 15% наблюдений (~2025-05-21 – 2025-06-29)

- **Почему random split некорректен**: 
  1. Нарушается временная структура – будущие значения могут попасть в обучающую выборку
  2. Возникает утечка данных – модель "видит" то, что должно быть неизвестно при прогнозе
  3. Невозможно оценить реальную прогностическую способность в условиях, приближенных к реальным
  4. Временные ряды имеют автокорреляцию, и случайное перемешивание разрушает эту зависимость

### 4.2. Признаки для baseline-моделей

- **Лаги**: 1, 24, 168 часов (прошлый час, прошлый день, прошлая неделя)
- **Rolling-признаки**: 
  - rolling_mean_24, rolling_std_24 (дневное окно)
  - rolling_mean_168, rolling_std_168 (недельное окно)
- **Календарные признаки**: 
  - hour_sin, hour_cos (циклическое представление часа)
  - dow_sin, dow_cos (циклическое представление дня недели)
- **Обработка пропусков**: удалены первые 168 строк (максимальный лаг/окно) после создания признаков
- **Масштабирование**: использован StandardScaler, обученный только на train данных и примененный к validation и test

## 5. Модели и эксперименты (B1, B2, B3, R1)

### B1 (naive-last)
- **Принцип**: прогноз = последнее известное значение (shift 1)
- **Особенности**: самый простой baseline, не требует обучения
- **Преимущества**: быстро, служит нижней границей качества

### B2 (moving-average)
- **Принцип**: прогноз = среднее значение за последние 24 часа
- **Особенности**: сглаживает суточную сезонность, но имеет задержку
- **Преимущества**: простой, устойчив к шуму

### B3 (ridge-lag-features)
- **Принцип**: линейная регрессия с L2-регуляризацией на engineered features
- **Особенности**: использует лаги, rolling статистики и календарные признаки
- **Преимущества**: учитывает сезонность, интерпретируем

### R1 (gru-forecast)
- **Принцип**: рекуррентная нейросеть с оконным представлением ряда
- **Параметры**:
  - window_size = 168 (неделя данных)
  - hidden_size = 128, num_layers = 2, dropout = 0.2
  - batch_size = 64, learning_rate = 0.001
  - optimizer = Adam, loss = MSELoss
  - max_epochs = 50, early_stopping = 10
- **Сохранение модели**: лучшая модель сохраняется по минимальной валидационной loss

**Основная метрика выбора**: MAE (средняя абсолютная ошибка)
**Дополнительные метрики**: RMSE, MAPE

## 7. Анализ

**Почему наивный baseline (B1) оказался слабым**: 
Naive-last (прогноз = предыдущее значение) не учитывает сезонность, что приводит к задержке в прогнозе и накоплению ошибки. На данных с ярко выраженной суточной периодичностью такой подход неприменим.

**Moving average (B2) и его ограничения**: 
Скользящее среднее сглаживает краткосрочные колебания, но запаздывает при резких изменениях. Окно 24 часа хорошо отражает среднее дневное значение, но теряет информацию о форме суточного цикла.

**Ridge на признаках vs простые baseline**: 
Добавление лагов (1, 24, 168 часов) позволило модели уловить суточную и недельную периодику. Rolling статистики добавили информацию о локальной волатильности. Календарные признаки помогли зафиксировать циклическую природу времени. В результате линейная модель с регулярной изацией показала значительное улучшение.

**Почему GRU помогла**: 
Нейросетевая архитектура способна автоматически извлекать сложные временные зависимости, которые не улавливаются линейной моделью. GRU запоминает долгосрочные паттерны (благодаря window=168) и лучше моделирует нелинейные взаимодействия между разными временными лагами. Кривые обучения показывают стабильную сходимость без переобучения.

**Влияние тренда и сезонности**: 
Ярко выраженная суточная сезонность (24 часа) и недельная сезонность (168 часов) делают задачу предсказуемой при правильном выборе окна. GRU с окном 168 часов может "видеть" целую неделю данных, что позволяет улавливать как внутридневные, так и междневные паттерны.

**Потенциальные утечки данных**: 
При построении признаков использовались только прошлые значения (shift, rolling с учетом порядка). Масштабирование обучено только на train. Temporal split сохраняет хронологию. Это исключает утечки из будущего.

**Почему выбор по validation принципиален**: 
Test должен использоваться только один раз для финальной оценки. Если бы мы выбирали модель по test, это привело бы к переобучению под тестовую выборку и нечестной оценке обобщающей способности.

**Наиболее показательные ошибки**: 
График остатков GRU показывает, что ошибки распределены нормально с центром около нуля, но есть небольшая гетероскедастичность – ошибки увеличиваются на пиковых значениях ряда. Это указывает на возможность улучшения модели для экстремальных значений.

## 8. Итоговый вывод

**Базовый подход для такой задачи**: 
Я бы рекомендовал Ridge регрессию на хорошо подобранных признаках как базовый подход. Она проста в реализации, интерпретируема и дает хорошее качество (MAE = 6.23). Для быстрого прототипирования этого достаточно.

**Когда достаточно простого baseline**: 
Если ряд имеет четкую сезонность и нет сложных нелинейных взаимодействий, линейная модель с правильными признаками (лаги, скользящие статистики, календарь) работает отлично. Это экономически эффективно и не требует больших вычислительных ресурсов.

**Когда переходить к GRU/нейросетям**: 
Нейросети оправданы, когда:
- Есть сложные нелинейные зависимости
- Требуется автоматическое извлечение признаков
- Данные очень большие (десятки тысяч наблюдений)
- Важно уловить долгосрочные зависимости

**Главный урок**: 
Корректная валидация временных рядов – это не просто техническая деталь, а фундаментальное требование для получения честной оценки модели. Temporal split и предотвращение утечек данных критически важны для построения прогнозных моделей, которые будут работать в реальных условиях.
